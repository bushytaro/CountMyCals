Cree une application web CountMyCals avec Next.js (App Router, TypeScript) et Supabase comme backend
(base de donnees + authentification). Voici ce dont j'ai besoin pour cette premiere version :

## 1. Setup

- Projet Next.js + TypeScript + Tailwind CSS.
- Client Supabase configure via variables d'environnement https://yfvlzmzxzzqzcxubmlgm.supabase.co et
  sb_publishable_Jcvns7P2ohpnAYIhK6D7Tw_8jccmdl_ (je les ajouterai dans les secrets Replit).
- J'ai deja le schema SQL complet (tables, types, Row Level Security) que j'ai execute directement
  dans l'editeur SQL de Supabase. Les tables principales sont : `recettes`, `recette_ingredients`,
  `recette_sauces_compatibles`, `ingredients_canoniques`, `produits_magasin`, `magasins`,
  `profils_utilisateurs`, `utilisateur_magasins`, `plans_repas`, `plans_repas_items`.
  Ne recree pas ces tables, utilise-les telles quelles.

## 2. Authentification

- Page d'inscription / connexion avec Supabase Auth (email + mot de passe).
- Apres inscription, redirection vers un flow d'onboarding en plusieurs etapes qui cree la ligne
  correspondante dans `profils_utilisateurs` :
  1. Objectifs alimentaires : kcal, proteines (g), glucides (g), lipides (g).
  2. Budget course hebdomadaire (en euros).
  3. Magasins disponibles : cases a cocher parmi Leclerc / Auchan / Carrefour (table `magasins`),
     enregistres dans `utilisateur_magasins`.
  4. Equipement de cuisine disponible : cases a cocher Four / Micro-onde / Casserole / Poele / Mixeur
     (colonnes booleennes sur `profils_utilisateurs`).
- Apres l'onboarding, redirection vers un tableau de bord simple (page `/dashboard`).

## 3. Dashboard (version minimale pour tester)

- Affiche le profil de l'utilisateur (objectifs, budget, magasins, equipement), avec un lien pour le modifier.
- Une page `/recettes` qui liste simplement toutes les recettes presentes dans la table `recettes`
  (nom, categorie, temps de preparation), juste pour verifier que la lecture depuis Supabase fonctionne.
  Pas besoin de logique de selection/algorithme a ce stade, juste un affichage brut.

## 4. Ce qu'il ne faut PAS faire dans ce premier prompt

- Pas de logique de generation de plan de repas (viendra dans un prompt suivant).
- Pas d'integration Stripe ni Crisp pour l'instant.
- Pas de scraping.
- Reste simple : l'objectif est d'avoir un squelette fonctionnel (auth + onboarding + lecture de donnees)
  que je peux tester avant d'ajouter la logique metier.

## 5. Donnees de test

J'importerai moi-meme un petit jeu de recettes de test directement dans Supabase (table `recettes` +
`recette_ingredients` + `recette_sauces_compatibles`) pour verifier que la page `/recettes` les affiche
correctement. Pas besoin de generer de fausses donnees.
